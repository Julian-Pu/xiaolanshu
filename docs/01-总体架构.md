# 01 · 总体架构

## 1. 产品定位

小蓝书是一款**内容种草社区**：用户浏览双列信息流 → 阅读图文笔记 → 点赞/收藏/评论/关注 → 发布自己的笔记 → 在话题与搜索中发现内容。核心是「内容 - 创作者 - 互动」三角。

主要角色：

- **游客**：可浏览信息流与笔记详情
- **注册用户**：发布、互动、关注、私信
- **创作者**：个人主页沉淀内容与粉丝

## 3. 双端形态设计

| 维度 | 移动端（Android） | 网页端 |
|---|---|---|
| 框架 | Kotlin + Jetpack Compose（Material 3） | React 18 + Vite |
| 形态 | 原生 App（单 Activity + Navigation） | SPA |
| 布局 | 底部 TabBar（首页/发现/发布/消息/我的） | 左侧导航 + 中间双列信息流 + 右侧栏 |
| 导航 | Navigation Compose 路由 | React Router v6 |
| 状态 | ViewModel + StateFlow / remember 状态 | Zustand（auth 等） |
| 网络 | Retrofit + OkHttp（自动带 JWT） | axios（拦截器统一注入 token） |
| 与后端 | 同一套 REST API | 同一套 REST API |

**双端共用一套 API**，保证产品逻辑一致，仅视图层与交互形态不同。

## 4. 后端分层（Spring Boot）

```
HTTP 请求
  → Controller（@RestController，入参校验 Bean Validation）
  → 拦截器链（CORS / 限流 RateLimitInterceptor / JWT 可选登录 AuthInterceptor）
  → Service（业务规则：计数、通知、幂等，@Transactional）
  → JdbcTemplate 数据访问（SQL 参数化，MySQL 兼容方言）
  → 统一响应 { code, message, data } + 全局异常处理
```

要点：

- **模块化单体**：按业务域分包（auth/user/post/feed/interaction/comment/topic/search/notification/message/upload），每个模块 Controller + Service + DTO，后续可平滑拆微服务。
- **统一响应与错误码**：`{ code: 0, message, data }`，非 0 为错误；`GlobalExceptionHandler` 统一收口（业务异常/参数校验/上传超限/404/兜底 500）。
- **鉴权**：JWT（HS256，`jjwt`），`Authorization: Bearer <token>`；`AuthInterceptor` 可选登录——游客放行，需要登录的接口用 `CurrentUser.require(request)` 判定。
- **数据访问**：`JdbcTemplate` + 显式 SQL（MySQL 兼容方言），`schema.sql` 自动建表；开发用 H2（MODE=MySQL），生产切 MySQL 仅改连接配置。
- **限流**：内存令牌桶 `RateLimitInterceptor`（每 IP 每分钟 N 次），生产可换 Redis。

## 5. 关键业务链路

### 5.1 发布笔记

```
用户（双端） → 上传图片(POST /api/upload/image → 本地磁盘/OSS URL)
            → POST /api/posts { title, content, images, topicId }
后端：校验 → 写 posts 表 → 话题 post_count+1 → 用户 post_count+1 →（扩展：异步通知粉丝）
```

### 5.2 浏览信息流

```
GET /api/feed?tab=recommend|following
后端：following → 查关注列表 → 取关注者笔记（时间倒序）
      recommend → 热度分排序：score = like*3 + comment*5 + view*0.2
      → 分页 → 批量组装作者/话题/登录态互动状态 → 返回
```

### 5.3 互动（赞/藏/评论/关注）

- 写入关系表（likes/collects/follows/comments），**事务内同步更新** posts 上的计数字段（读多写少，避免 count 查询）。
- 产生通知记录（notifications），接收者在自己主页查看。

### 5.4 搜索

- 起步：`LIKE '%q%'`（posts.title/content、users.nickname），可排序。
- 生产：内容量上来后引入 ElasticSearch / 云搜索，倒排索引 + 分词 + 高亮（见 05 演进）。

### 5.5 私信

- 起步：conversations + messages 两张表，REST 轮询。
- 生产：WebSocket（长连接）推送 + 已读回执 + 离线消息（见 05 演进）。

## 6. 架构演进路线

```
MVP（本仓库）              →  成长期                →  成熟期
Spring Boot 模块化单体      →  按域拆分服务          →  微服务 + 服务网格
H2 / 单 MySQL              →  MySQL 主从 + 分库     →  分库分表 / TiDB
本地磁盘                   →  OSS + CDN             →  多云容灾
LIKE 搜索                  →  ES 集群               →  ES + 向量检索（图文语义）
REST 轮询消息              →  WebSocket 网关        →  独立 IM 服务
```
