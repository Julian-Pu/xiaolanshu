## 2. 对标小红书的差距分析

### 2.1 架构层面

| # | 差距 | 现状 | 影响 | 建议 |
|---|---|---|---|---|
| A1 | 无数据缓存层 | Redis 仅用于验证码；feed/详情/热门每次都查库 | 数据量大后查询慢、热点放大 | 热点笔记/feed 页结果 Redis 缓存（TTL 短）+ 缓存失效（写操作主动删）；见 docs/06 |
| A2 | 推荐算法过简 | 静态热度分，无时间衰减、无个性化 | 老笔记永久霸榜，新内容曝光差；所有用户同排序 | 已升级为时间衰减热度（本轮）；中期加用户兴趣标签、离线物料池 |
| A3 | 计数一致性与补偿 | like/collect/comment 冗余计数靠事务内 update | 极端并发下可能计数漂移 | 已基本一致；生产加对账任务（定时重算计数） |
| A4 | 私信为 REST 轮询 | 无长连接/推送 | 消息延迟、体验差 | 中期上 WebSocket / Server-Sent Events；已留接口设计（docs/05） |
| A5 | 无前端 MVVM/状态分层 | Android Screen 直接调 ApiClient | 页面状态与网络耦合，难测试难复用 | 中期抽 Repository + ViewModel（StateFlow） |
| A6 | 图片服务裸奔 | 原图直传直读，无压缩/裁剪 | 流量大、加载慢 | 生产接对象存储 + 图片处理（缩略图/水印）；App 端已用 Coil 占位 |

## 3. 本轮已实施改进（v1.1.0）

### 后端
1. **feed 时间衰减热度**：`score = (like*3+collect*2+comment*5+view*0.2) / (发布小时数+2)^1.5`，避免老笔记霸榜（Java 侧计算保证 H2/MySQL 跨库一致）。
2. **话题频道流**：`GET /api/feed?tab=topic&topicId=N`，支持首页频道。
3. **相关推荐**：`GET /api/posts/{id}/related?limit=6`，同话题 → 同作者 → 全站热度，排除自身。
4. **收藏/赞过**：`GET /api/users/me/collects`、`GET /api/users/me/likes`（分页，含互动状态）。

### Android（v1.1.0 APK）
1. 首页频道胶囊 tab（推荐/关注 + 全部话题），横向滑动。
2. 下拉刷新（PullToRefresh）+ 上拉自动加载更多 + 底部「已经到底啦」。
3. 个人主页三 tab：笔记 / 收藏 / 赞过（他人主页仅笔记）。
4. 详情页「相关推荐」横滑卡片，点击直达新详情。

### Web
1. 首页频道 tab 同步（横向滚动 + 话题频道），瀑布流复用。

### 第六轮（v1.7.0，第二批：推荐 v2 + Redis 缓存 + 私信体验 + Web 深色细节）
1. **推荐个性化 v2（协同过滤冷启动）**：`FeedService` 推荐流在「时间衰减热度 + 兴趣标签」之上新增 ItemCF 简化版——取我最近点赞/收藏的笔记 → 找共同互动的"相似用户" → 相似用户互动过的其他笔记按人数加权（1 人 ×1.4 → 3 人及以上封顶 ×2.2），并排除已读/自己发布的笔记；无互动冷启动自动回落到热度+兴趣。实测：有共同互动的 user2 推荐流中相似笔记升至首位，冷启动用户仍为热度序。
2. **笔记 Redis 热点缓存**：新增 `PostCacheService`（key `cache:post:{id}`，TTL 120s，`xiaolanshu.cache.redis-enabled` 开关，Redis 不可用自动降级直查）；未登录公共详情走缓存（登录用户含个性化互动字段不缓存）；编辑/删除时主动失效；互动计数变化最多滞后一个 TTL，由对账任务兜底。
3. **计数对账任务**：新增 `CountReconcileTask`（每小时整点 @Scheduled 重算 like/collect/comment 计数与话题 post_count，消除并发漂移）+ `POST /api/admin/reconcile-counts` 手动触发。实测 changedRows=21。
4. **私信已读回执 / 正在输入**：WS 协议新增 `typing`（转发对端 "对方正在输入…"，3 秒自动消失）与 `read`（标记已读 + 回执对端 `read_ack`）；REST 新增 `POST /api/conversations/:id/read` 兜底；会话列表带 `unreadCount` 未读角标（Android 红点/Web 徽标），消息气泡显示已读/未读。三端实测：typing/read_ack/message 帧全链路通过。
5. **Web 深色模式细节打磨**：输入框/编辑器背景与文字改 CSS 变量适配、内容图（瀑布流/详情/话题/预览）深色下轻微压暗、登录页深色渐变、深色滚动条与文本选区、聚焦光晕。
6. 版本：versionCode 9 / versionName 1.7.0。

### 第七轮（v1.8.0，第三批：图片处理管线 + 搜索拼音纠错 + 内容安全审核）
1. **图片处理管线**：新增 `ImageProcessor`（Java ImageIO 内置实现）——上传图片（jpg/png）自动生成最长边 ≤600px 缩略图并叠加右下角半透明「小蓝书」水印（`xiaolanshu.image.watermark` 可关）；gif/svg/webp 回落原图。上传接口返回 `{url, thumbUrl}`；卡片 DTO 新增 `coverThumb`（约定式推导，存量数据自动生效），三端信息流/列表用缩略图、详情保持原图。实测：1200×1600 测试图 → 缩略图 450×600 + 水印 OCR 可识别「小蓝书」。
2. **搜索拼音纠错**：引入 pinyin4j，搜索词含拉丁字母时对全部已发布笔记标题、用户昵称做全拼/首字母匹配（演示规模内存索引，生产换 ES 拼音分词器），与原有 LIKE 合并查询；纯中文搜索回归不受影响。实测：kafei/kf → 咖啡笔记、xiaolan/xl → 用户小蓝、azhe → 阿哲，全绿。
3. **内容安全审核（文本机审 + 人工复核队列）**：新增 `SensitiveWordFilter`（内置演示敏感词库 + `xiaolanshu.audit.enabled` 开关）与 `AuditService`——发布/编辑/评论统一过检，命中返回 400 提示命中词；审核留痕写入 `audit_logs` 表（独立 REQUIRES_NEW 事务提交，业务事务回滚也不丢失），`GET /api/admin/audit/logs` 供人工复核。实测：发布「博彩」/评论「刷单」/编辑「赌博」均拦截且原内容保留，日志含 3 条命中记录。
4. 踩坑记录：审核日志若随业务事务写入会因拦截异常一并回滚（日志查不到）——必须独立事务先提交再抛业务异常；pinyin4j 输出带声调数字需自封装去音调；com.github.promeg:tinypinyin 不在 Maven Central（换 com.belerweb:pinyin4j）。
5. 版本：versionCode 10 / versionName 1.8.0。

### 第八轮（v1.9.0，第四批：存储抽象层 + 推荐离线物料池 + 多端实时通知推送）
1. **存储抽象层**：新增 `StorageService` 接口（save/delete）+ `LocalFileStorage` 本地实现（URL `/uploads/<category>/<filename>`，delete 带目录穿越防护）；图片/视频上传全部改走抽象接口，生产可直接替换 OSS/COS/MinIO 实现而无需改业务代码。实测：上传 → 落盘 + thumbUrl 链路回归通过。
2. **推荐离线物料池（召回/排序演示版）**：新增 `recommend_candidates` 表 + `RecommendationMaterialTask`（每小时 @Scheduled 定时重建 + `POST /api/admin/rebuild-material` 手动触发）：为每个用户按「召回（全量已发布 → 排除已读/自己）+ 排序（时间衰减热度 × 兴趣加成 × 协同过滤加成）」预计算 TopN 候选（含主导因素 hot/interest/cf）落表；feed 推荐流**在线直读池子**（6h 新鲜度检查），池缺失/过期自动回落实时计算。演示用 Spring 定时任务替代生产 Spark/Flink 离线链路。实测：手动重建 users=5 candidates=48；user2 推荐流 5 条全来自池、不含自己笔记。
3. **多端实时通知推送（演示版）**：通知产生点（点赞/收藏/评论/关注）落库后经现有 /ws 连接推 `{"type":"notify","notification":{...}}` 帧——Android 收到后刷新通知列表/未读数并弹系统通知栏（新增 POST_NOTIFICATIONS 权限 + 「互动通知」渠道，点击回到 App）；Web 收到后自动刷新通知列表。生产可扩展厂商推送通道（FCM/厂商通道 + Web Push）。实测：user3 点赞+评论 user2 笔记 → user2 WS 收到 notify 帧（内容含 refId/type/actorId）、通知落库，全绿。
4. 版本：versionCode 11 / versionName 1.9.0。

## 5. 已知技术债
- feed 推荐 Java 侧全量排序，数据量 >10 万需改 Redis 预热 + SQL 分页（见 docs/06）。
- 计数靠事务内 update，极端并发需对账。
- Android 无统一状态管理，页面间不共享数据（消息角标等需跨页状态）。
- 明文 HTTP 仅限开发；上线必须 HTTPS（见 docs/07 安全清单）。
