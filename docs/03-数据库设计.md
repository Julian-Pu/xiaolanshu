# 03 · 数据库设计

> 可执行版本：`server/src/main/resources/schema.sql`（MySQL 兼容方言；开发环境由 H2 以 `MODE=MySQL` 模式执行，生产环境可直接用于 MySQL 8）。

## 1. ER 概览

```
users ──< follows >── users
users ──< posts >──── topics（笔记归属话题，可空）
posts ──< comments >── users
posts ──< likes / collects >── users
posts ──< notifications >── users
users ──< conversations >── messages
```

|---|---|---|

| bio | VARCHAR(255) | 简介 |
| gender | VARCHAR(10) | male / female / secret |

| follower_count | INT | 粉丝数（冗余计数） |
| post_count | INT | 发布数（冗余计数） |

| 字段 | 类型 | 说明 |

## 3. 索引设计

| 表 | 索引 | 用途 |
|---|---|---|
| posts | idx_posts_created (created_at DESC) | 信息流时间排序 |
| posts | idx_posts_user (user_id, created_at DESC) | 个人主页笔记 |
| posts | idx_posts_topic (topic_id) | 话题聚合 |
| comments | idx_comments_post (post_id, created_at) | 评论列表 |
| notifications | idx_notif_user (user_id, is_read) | 通知中心 |
| messages | idx_msg_conv (conversation_id, created_at) | 会话消息 |
| follows | idx_follows_follow (follow_user_id) | 粉丝列表 |

## 4. 一致性策略

- **冗余计数**：`like_count / comment_count / collect_count / follower_count / post_count` 等采用**事务内同步更新**（点赞 → 关系表插入 + posts.like_count+1 同一事务），保证强一致；读侧零聚合查询。生产高并发下可改异步（MQ + 最终一致），见 docs/05。
- **软删除**：笔记删除置 `status='deleted'` 而非物理删除，保留审计与粉丝信息流幂等；删除评论后**重算**评论计数保证一致性。
- **时间统一**：存 UTC（`Instant.toString()`），应用层按需转本地。

## 5. 生产 MySQL 切换要点

- `schema.sql` 即为 MySQL 兼容方言，生产直接执行；开发环境 H2 以 `MODE=MySQL` 运行同一份脚本（`application.yml` 改 url/driver 即可切换）。
- 建议：`utf8mb4` 字符集；热点表（likes/collects）按 user_id 分表（演进）。
