# 05 · 部署架构

## 1. 开发环境（本机零配置）

```
用户电脑
├── server :3000   Spring Boot API + H2 文件库 + 本地磁盘图片（自动播种演示数据）
├── web    :5173   Vite dev（/api、/uploads 代理到 3000）
└── android        Android Studio 运行（模拟器经 10.0.2.2:3000 访问宿主机）
```

- 启动：`server: .\mvnw.cmd spring-boot:run`；`web: npm install && npm run dev`
- 数据文件：`server/data/xiaolanshu.*`（H2）；图片：`server/uploads/`
- 后端检测到 `web/dist` 存在时自动托管网页端静态文件（同端口 3000 访问，含 SPA 路由兜底）

## 2. 生产环境拓扑

```
用户
 └─ CDN（静态资源/图片加速）
     └─ Nginx（TLS 终止 · 反向代理 · 限流 · 静态托管 web/dist）
         ├─ Spring Boot 服务实例 ×N（Docker 多副本，无状态）
         │    ├─ MySQL 8 主库
         │    │   └─ 从库（读扩展，演进）
         │    ├─ Redis（会话/热榜/限流/缓存）
         │    └─ OSS（图片存储）+ 消息队列（异步，演进）
         └─ 日志/监控：ELK + Prometheus + Grafana（演进）
```

无状态设计要点：JWT 无会话存储、图片存 OSS、业务数据在 MySQL → 服务实例可水平扩容，Nginx `upstream` 负载均衡。

## 3. Docker Compose（生产参考编排）

| 服务 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| nginx | nginx:alpine | 80 | 静态资源 + 反代 /api |
| server | eclipse-temurin:17-jre（自建 Dockerfile，`mvnw package` 产物） | 3000 | API 服务 |
| mysql | mysql:8.0 | 3306 | 业务库（生产切 MySQL） |
| redis | redis:7-alpine | 6379 | 缓存/限流 |

```bash
# 生产栈参考（本仓库提供 docker-compose.yml 与 nginx/ 配置模板）
docker compose up -d
```

## 4. 关键配置项（server/application.yml）

```yaml
server:
  port: 3000
spring:
  datasource:
    # 开发：H2；生产改 url/driver-class-name 为 MySQL
    url: jdbc:h2:file:./data/xiaolanshu;MODE=MySQL;...
  sql:
    init:
      mode: always          # 自动执行 schema.sql 建表
xiaolanshu:
  jwt:
    secret: <生产替换为 >=32 字节高熵随机串>
    expires-days: 7
  upload-dir: ./uploads
  web-dist: ../web/dist
  rate-limit:
    max-per-minute: 300
```

## 5. 上线清单（生产必做）

- 安全：HTTPS、JWT_SECRET 高熵、密码强度校验、接口限流放大、防 XSS/CSRF、SQL 参数化（已内置）
- 合规：隐私政策、用户协议、未成年人保护、内容审核（图片 OCR + 文本敏感词，接入第三方审核）、实名与内容举报通道
- 数据：MySQL 主从、定时备份、OSS 生命周期管理
- 可观测：访问日志、慢 SQL、错误告警、指标监控
- 发布流程：CI（lint + 单测 + 构建）→ 灰度 → 全量

## 6. 演进架构（微服务拆分）

```
拆分时机：单模块变更频繁 / 团队分域 / 流量瓶颈
┌─ 网关（Nginx/API Gateway）
├─ user-service（用户/关注/粉丝）       MySQL: users 库
├─ feed-service（信息流）               Redis 热榜 + MySQL
├─ post-service（笔记/话题）            MySQL: posts 库
├─ interaction-service（赞/藏/评）      MySQL: 互动库 + MQ
├─ search-service（ES）                ElasticSearch
├─ notify-service（通知）              MQ + WebSocket
└─ im-service（私信）                  WebSocket 网关 + MySQL
```

依赖演进：同步调用 → MQ 异步（通知、计数、粉丝信息流 fan-out）→ 最终一致。

> MQ 的完整落地方案（消息契约、Outbox、幂等、重试死信、分阶段迁移）见 **[06-消息队列异步化设计](06-消息队列异步化设计.md)**。
